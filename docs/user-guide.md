# 使用说明

这个项目包含一个网站和一套自动更新程序。看数据时打开网站；更新数据时替换一个 Excel。ZIP 里的其他文件用来保证网站能长期维护，平时不需要逐个操作。

**首发版本已于 2026-09-23 上线并验证。** [打开网站](https://lawrence35952563.github.io/National-Power/)。首发时本地与 GitHub Actions 的 34 项测试通过，详见[首发验收记录](qa/browser-release-2026-09-23.md)。2026-09-24 上轮阅读体验修订已通过本地与 Actions 的 42 项测试，并完成桌面、手机视口及线上复验，详见[上轮验收记录](qa/browser-release-2026-09-24.md)。

本说明已更新为本轮表格与导航交互修订的用法。**本轮新增 8 项测试，合计 50 项本地测试通过，发布及线上验收尚待完成。** 当前进度见[本轮验收记录](qa/interaction-release-2026-09-24.md)和[发布状态](deployment-status.md)。

## 怎么看网站

正式地址：[国家长期能力综合排名](https://lawrence35952563.github.io/National-Power/)。是否已完成发布及线上检查，以仓库首页链接的[交付说明](../DELIVERY.md)为准。

如果是在电脑上查看交付 ZIP，先完整解压，再双击 `dist/offline.html`。这一个文件已内嵌数据和下载内容，无需保留相邻文件夹。离线副本只包含打包时的数据，不会随线上网站自动更新。

第一次阅读，建议按 **研究导读 → 综合排名与实体档案 → 八个领域与具体字段 → 数据与方法** 进入。先理解研究关注的长期行动条件，再选一个熟悉的实体看能力结构；需要追问某个结果时，沿领域解释回到字段与原始记录。

| 想做什么 | 打开哪里 |
| --- | --- |
| 理解研究在问什么、怎样开始阅读 | 研究导读；首页示例使用当前工作簿数据 |
| 看总体排序、搜索一个实体 | 综合排名，可切换简单榜单、领域总览，独立显示公式参考值 |
| 看某个实体的能力结构和底层记录 | 点击实体名称，分别读三项领域名次和五项基础条件；通过领域定位栏查看主题与记录 |
| 理解领域之间的联系、找到具体依据 | 八个领域，选择领域后沿主题进入字段 |
| 比较几个实体和字段 | 排名页加入比较篮，或直接进入实体比较；选择 2–5 个实体和最多 8 个原字段 |
| 查找一个字段及各实体记录 | 数据与方法 → 字段目录，也可从领域解释进入 |
| 像翻 Excel 一样查看全部数据 | 数据与方法 → 完整数据，切换工作表、主题列或自定义列 |
| 核对一个数值或公式 | 点击数值，查看原单元格；展开“高级溯源：原始存储与公式” |
| 了解评分、公式与作者判断的关系 | 数据与方法 → 来源与方法 |
| 保存 Excel、CSV、JSON 或离线版 | 数据与方法 → 下载文件 |

### 排名、比较和完整数据

综合排名默认使用“简单榜单”，突出综合名次和分类。切换“领域总览”可并排查看三项领域名次与五项基础评分；“显示公式参考值”是独立开关。在列表中加入想比较的实体，再选择“比较已选实体”。搜索或切换分类时，已选实体继续保留，最多 5 个。

比较页先并列展示综合位置与领域结构。继续比较具体依据时，可按关键词、工作表和已有解释主题查找，勾选最多 8 个原字段。切换筛选不会移除已选字段；可单独移除或清空字段选择。组合字段仍按原规则分项显示，因此显示行数可能多于所选原字段数。

完整数据保留两种搜索：上方搜索实体或单元格内容；“选择显示字段”内搜索列名或列字母。列搜索只缩小可选项范围，不改变已经勾选的列。可先选“主题列组合”，再自行增减为“自定义列”；“恢复完整原表”恢复全部字段，并包含辅助行。用“紧凑行距”调整显示密度，手机上仍可左右滑动宽表，实体列与表头固定。

### 实体页怎样定位记录

实体档案以紧凑方式展示三项领域名次和五项基础条件。点击领域，或使用随滚动保留的“领域定位”下拉框，可直接到达该领域；“返回结构”回到上方概览。记录沿既有解释主题组织，未归入主题的已填字段放在“其他记录”，未记录项与辅助字段仍可展开查看。

各字段的“含义与口径”继续保留，按需展开；点击数值查看原值。领域中的“定位原表”会带上当前实体的名称筛选，便于在宽表中核对。主题只改变阅读与显示方式，不增加研究分组、权重或结论。

### 返回、刷新与分享

筛选、排序、显示列、比较实体及字段选择会写入地址栏。可以直接复制地址分享；比较页也提供“复制分享链接”。接收者打开的是相同的选择与筛选，不会继承你的页面滚动位置。

在当前浏览器会话中，从字段或实体页使用浏览器后退，会恢复此前那次访问的展开内容、页面及表格滚动位置；同一路径的不同历史访问分别保存。刷新当前页也会使用已保存的状态。顶部导航进入该栏目默认视图，适合重新开始查看；它不等同于浏览器后退。

### 名次与评分怎样读

政治、经济、军事使用名次，数值越小位置越靠前。其余五领域的主要评分等级依次为：**1 明显短缺、2 依赖外部条件、3 够用、4 基本完整且单项突出、5 充足且有余量**。网页使用固定等级与文字说明，小数评分保留原值，不用条形长度表示能力倍数。补充实体中的原始标记单独阅读，不套用正常评分等级。

“公式参考值”不是百分制总分。实体页可展开“计算参考与综合名次的关系”；方法页可展开公式、权重和特殊修正。字段的单位、年份、来源只在有明确记录时显示；没有显示表示资料未注明，不代表已知但被隐藏。空白数值、零与原表错误仍分别保留。

## 以后只更新哪个文件

**唯一需要替换的文件是：[`data/source/national-power.xlsx`](../data/source/national-power.xlsx)。**

其中 `data/source` 是文件夹，`national-power.xlsx` 是文件名。你电脑上的工作文件可以继续叫“综合国力2.0.xlsx”；上传的副本需要使用这个固定文件名，自动程序才知道读取哪一个。

按现有表结构修改国家数值、排名或评分时，网站不需要另外改。操作顺序如下：

1. 在 Excel 中完成修改，确认公式已重新计算，然后保存。保留现有工作表名称和表头。
2. 准备一份名为 `national-power.xlsx` 的公开副本。直接上传前清理文档属性中的作者、最后编辑者等个人信息；文件会连同历史版本保存在公开仓库中。
3. 打开 GitHub 的 [`data/source` 文件夹](https://github.com/Lawrence35952563/National-Power/tree/main/data/source)，确认当前分支是 `main`。
4. 选择 **Add file → Upload files**，上传该副本，替换原来的同名文件，再点击 **Commit changes** 保存更改。
5. 打开仓库的 [Actions](https://github.com/Lawrence35952563/National-Power/actions)，找到最新一次 **Validate, build and deploy Pages**。这就是本项目的自动更新任务。
6. 等待 `build` 和 `deploy` 两部分都显示成功，再刷新网站。

自动任务会读取新版 Excel、检查数据、生成全部页面和下载文件，再发布到 GitHub Pages。你不需要更新每个实体页，也不需要自己生成 CSV 或 JSON。

### 只改一个数字时

在这份 Excel 中找到该实体、该指标的原始单元格，修改后让 Excel 完成公式重算并保存，再替换仓库里的同名文件即可。网站全部入口共用自动生成的数据层，不存在还要手工改另一份网页数字的问题。

但原表中有些领域名次、综合名次和评分是作者录入的结果，不是公式。修改底层数据不会自动改变这些人工结果。如果你的研究判断也变了，应在同一个 Excel 中同步修改相应排名或评分；网站不会自行推算或替你决定新的名次。

军事的点号组合字段会在网页中分列显示，仍读取同一个 Excel 原单元格。原表不用为了网页额外维护两份数据。数值单元格可能已经丢失输入时的小数末尾零；程序不会补猜这些零，也不会把没写出的第二项当作 0。若需要精确保留点后编码，先确认其含义，再保留完整的文本记录；不要仅靠改变小数显示位数恢复已经丢失的记录。

研究版本（例如 2.0）和数据版本分开显示。每次 Excel 内容改变，数据指纹自动改变，不需要为了更新一个数字再编辑配置文件中的研究版本。

### 什么时候需要改其他文件

只改现有单元格里的数字、排名或文本，仍只维护 Excel。新增/删除工作表、改表头、拆分原始 Excel 列、改变综合公式或权重，以及修订文字解释，则需要维护者同步检查字段映射或说明。这属于结构或研究口径修改，不属于日常数字更新。

八领域导读的阅读分组、主题解释和字段链接保存在 `web/reading-guide.js`；报告释义和页码仍在 `config/reader-notes.json`。只有修订这些文字或字段关系时才需要维护它们，日常更新数字不用改。首页示例、实体页和比较继续从同一份 Excel 自动取数。

如果想交给我更新，直接提供最新版 Excel，并说“用这个版本更新 National-Power 网站”即可。项目内已提供导入程序，用于清理个人文档属性和检查文件。

新增工作表、调整列结构或改变评分公式也可以做，但这类修改涉及程序怎样理解数据，可能需要同步调整网站配置。遇到这种情况，把新版 Excel 和自动检查结果交给维护者处理，不需要自行研究配置文件。

## 更新没成功怎么办

Actions 中的黄点表示任务仍在运行，绿色对勾表示该项完成，红叉表示失败。**检查未通过时，新版本不会覆盖已经成功发布的网站。**

先打开失败的那次运行，点开带红叉的步骤。页面上的错误提示通常会说明问题出在哪里，例如公式没有保存计算结果、工作表结构改变或出现新的原表错误。

如需详细报告，在那次运行页面的 **Artifacts** 区域找到 `validation-and-build` 并下载。里面的 `validation.md` 是可读报告；部分早期失败只有 `validation.json`，如果没有报告文件，就保留失败步骤的提示。

**不必自己看懂所有报错。** 把运行链接、失败提示或下载的报告交给我即可。若涉及国家数值、评分含义或研究规则，由你决定是否修改；网站程序不会自行改研究结论。

如果自动任务全部成功，但页面仍像旧版，先刷新页面，再看网站下载页的“网站构建日期”和“工作簿保存日期”。若仍有疑问，提供这两个日期和 Actions 运行链接即可继续排查。

## 数据里的异常在哪里看

| 内容 | 位置 |
| --- | --- |
| 本次整理发现的原表问题及具体位置 | [Excel 检查报告](qa/excel-audit.md) |
| 当前数据的检查摘要 | 数据与方法 → 来源与方法，展开“本版本数据检查记录” |
| 某次新上传文件的检查结果 | 对应 Actions 运行中的 `validation-and-build` 报告 |
| 网站和部署实际验收到哪一步 | [验收记录](acceptance-review.md)与[发布状态](deployment-status.md) |

原表中的空白、零和计算错误含义不同，网站分别保留。检查报告也分两种情况：一般提示会保留原数据并说明限制；阻断问题会暂停新版本发布。现有检查报告记录的是对应版本，日后更新时应同时查看最新自动报告。

## 这些文件为什么要保留

你日常只接触 Excel 和网站。其他文件相当于自动加工和检查所需的工具，保留它们，以后才能继续自动更新。

| 文件或目录 | 通俗解释 | 平时要不要改 |
| --- | --- | --- |
| `README.md` | 打开仓库时看到的简短入口 | 通常不用 |
| `DELIVERY.md` | 这次完成了什么、还有什么待完成 | 交付或状态变化时更新 |
| `data/source/national-power.xlsx` | 你维护的原始研究数据 | **更新数据时替换它** |
| `web/` | 网站长什么样、按钮怎样工作 | 改界面时才需要 |
| `web/reading-guide.js` | 八领域阅读分组、解释及字段链接 | 修订导读文字时由维护者处理，更新数字不用改 |
| `scripts/` | 把 Excel 变成网站并检查错误的程序 | 通常不用 |
| `config/` | 工作表和字段的解释规则 | 表结构或研究规则变化时由维护者处理 |
| `tests/` | 防止更新破坏已有功能的自动检查 | 通常不用 |
| `.github/workflows/` | 告诉 GitHub 何时自动检查和发布 | 通常不用 |
| `docs/` | 使用方法、数据解释、问题与验收记录 | 需要查说明时打开 |
| `dist/` | 程序生成的成品网站，ZIP 中可离线打开 | 不手工修改；每次构建重新生成 |

CSV 是方便用 Excel 等工具阅读的分表副本，JSON 是供网站读取的数据文件。它们都从同一个源 Excel 生成，不是另外维护的数据源。

如需了解程序细节或在本地运行，见 [README 的维护者说明](../README.md#给网站维护者)。普通浏览和数据更新无需安装开发软件。
