# 读数含义与单文件更新复核

日期：2026-09-23。此记录补充首次 Excel 审计，修正“保存原始存储字符串就足以保证读者理解正确”的不足。

## 军事复合记录的展示错误

军事排名表 G、J、M、O、P 五列把两项记录放在一个单元格。166 个非空记录均为数值单元格，格式为 General；其中 24 个 XML 存储字符串包含二进制浮点序列化尾差。上一版虽然禁止将这些组合值用于数值图表，却直接将其 XML 字符串作为网页读数，导致尾差看起来成了点后的另一项数量。

| 位置 | 旧版主要显示 | 修正后的点前 / 点后记录 |
| --- | --- | --- |
| 中国 P3：军机、运输机 | `3309.2890000000002` | `3309` / `289` |
| 中国 J3：航空母舰、舰载机 | `8.1709999999999994` | `8` / `171` |
| 美国 J2：航空母舰、舰载机 | `20.126200000000001` | `20` / `1262` |
| 美国 O2：军用、民用卫星 | `247` | `247` / 未单列 |

现在数据层生成可读组合码与两个分项，所有网页入口共同使用。数值型记录用 15 位有效数字表达，必须能够解析回完全相同的原浮点数才允许拆分。现有 166 条均符合这一条件；不是统一取小数点后 3 位或 4 位。文本型记录保留原始数字串及前后零。

原 Excel、原 `raw`、公式和排名完全不改。原 XML 字符串仍在高级溯源中；原始工作表 CSV 继续保留审计表示，另提供 `military-components.csv` 便于读者查看分项。

## 仍不能从现有文件恢复的信息

- 63 个整数记录没有点后部分，其中包含 4 个明确的 0。点后没有记录不等于第二项为 0。
- 数值存储可能已经丢失原始输入的末尾零。例如当前比利时 P51 为 `108.7`，文件无法证明作者是否曾输入 `108.70`。程序不补猜。
- PDF 第 4 页明确说明核弹头/战略核潜艇、潜艇/核动力艇的双数量含义，其他三组由当前表头和报告解释对应。但 PDF 没有固定小数位、无点号或特殊 `.1` 标记规则。
- 因此第二列显示的是当前点后记录，并保留 `encoded` 状态；未认定为经过独立核实的装备清单，不参与图表或数值排序。有关标记需作者确认后才能进一步解释。

## 报告解释的呈现

重新读取 17 页 PDF，将其概念说明整理成 6 段概述、8 个领域说明，关联到 149 个现有字段。数量是当前映射覆盖量，不是独立研究指标数量。

解释出现在领域表、实体明细、指标详情、比较字段、单元格详情和方法页，附实际 PDF 页码。报告中的旧“政治”对应当前“稳定”，旧“发展”对应当前“政治排名”，按内容映射而不按旧名称硬接。旧报告的国家数值、排名和年份不会覆盖 Excel。

现有材料存在不一致时，在字段解释中说明，例如水源自给率名称与公式、不同增长字段的计算方式、两列同名铝、缩写矿产和复合标记。没有把历史总来源清单变成逐单元格已核实来源。

## 更新一个 Excel 的边界

同结构的数字、文本或作者排名更新只需替换 `data/source/national-power.xlsx`，再重建同一数据层；网页没有另一套独立维护的国家数值。公式需先在 Excel 重算并保存。人工录入的名次/评分需要作者在同一个 Excel 中同步维护，不会由网站重排。

本轮另外修复：朝鲜军费为零的说明只在当前值确实为零时显示；普通 Excel 保存重新带入打印设置时，不再因允许删除的 ZIP 部件差异导致清理测试误失败。数据版本由工作簿日期和指纹自动生成，与固定研究版本标签分开。

新增表、改表头、改编码规则或研究公式仍需要维护者检查配置和说明。未通过检查的新版本不会自动发布。

## 验证边界

本轮全套 34 项测试通过，独立构建与最终构建均通过。

除源单元格逐项保真检查，还验证分项含义、浮点尾差消除、缺项与零的区别，并以临时工作簿修改实际指标，检查 JSON、实体联结、分项和下载结果一起更新。单文件 HTML 的内嵌下载内容与生成文件逐字节核对。
